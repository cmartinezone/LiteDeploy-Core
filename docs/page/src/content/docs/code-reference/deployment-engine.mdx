**Script:** `components/Runtime/DeploymentEngine/LiteDeploy.DeploymentEngine.ps1`  
**Status:** Phase A scaffold on `dev`

BootInitializer calls the engine after the deployment source is mapped:

```text
BootInitializer
    → LiteDeploy.DeploymentEngine.ps1 -BootObject $bootObj
        → LiteDeploy.PreCheck.ps1
        → LiteDeploy.SelectWorkFlow.ps1
        → DeploymentSelection.json + DeploymentState.json
        → (not yet) Setup /NoReboot, WinPECT, reboot
```

PreCheck and SelectWorkflow **return** to the engine. They do not launch each other.

`BootObject` must already contain the loaded-environment `Config`, `ConfigPath`, and `DeploymentRoot`. The engine does not re-read the boot-WIM `BootConfig.json`.

## Parameters

| Parameter | Purpose |
| --- | --- |
| `-BootObject` | In-memory payload from BootInitializer (config, `DeploymentRoot`, share `PSCredential`) |
| `-Resume` | Planned FullOS resume; returns `NotImplemented` |
| `-StatePath` | Planned path for resume state |

## Theme

The engine resolves `BootObject.Theme` (or `Ui.Theme` on the promoted config) and passes `-Theme` to PreCheck and SelectWorkflow.

## Safety

- Credentials stay on `BootObject` in the parent process. They are never written to state JSON.
- Phase A does **not** wipe disks, run Setup, or reboot.
- Cancelled PreCheck or SelectWorkflow stops the engine with no destructive work.
